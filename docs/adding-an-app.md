# Adding an app

Design: homelab-infra `docs/proposals/homelab-apps/1-boundary-catalogue.md` (1.4 layout, 1.5 entry, 1.6 deployment, 1.7 deploy play, 1.8 flows, 1.9 environments) and `2-orchestration.md` 2.4.

Rule: guest config (exists, reachable, patched, testable) lives in homelab-infra; anything that makes a guest do its job lives here.

## Layout

```
catalog/<app>/
  app.yaml                  entry: status, size, flows, secrets, version, rollout, health, reboot, probes, tests
  role/                     Ansible role (defaults/, tasks/, handlers/); role_path = catalog/<app>/role
  files/                    templates and static files, referenced as {{ role_path }}/../files/...
  tests/l4.goss.yaml.j2     L4 app checks
  docs/design.md            why and how
  docs/runbook.md           operate, troubleshoot, restore
deployments/<zone>/<app>.yaml   one instance per zone: hosts, version, wave, vars
```

A complete skeleton is `catalog/_example/` (compose-based, status `example`; added by apps PR #10). Directories starting with an underscore are skipped by `scripts/catalog.py` but still linted. Copy it, rename, and adjust.

## Steps

1. Copy `catalog/_example/` to `catalog/<app>/` and fill `app.yaml` (1.5). New entries start as `beta` (stg only); `beta` to `stable` is Class C after 7 days green in stg.
2. Pin the version: `version.pin` plus its sha256 in `version.known`; `version.url` must contain `{version}`. The role verifies the download.
3. Write the role so it is idempotent and check-mode safe. Secrets are generated by `bao_create_secret` at deploy under `<zone>/secret/apps/<app>[/<host>]`; roles never see tokens and no values are committed here.
4. Declare `health` (shell, exit 0 = healthy, no secrets, hard timeout), `reboot.policy`, `probes`, and `peer_check` for `pair`/`cluster`.
5. Add `deployments/<zone>/<app>.yaml` (1.6). stg is wave 1; others follow `environments.yaml`. Banned vars and Jinja-in-values rules: 1.7.
6. Flows use the vocabulary in 1.8. Gateway-routed zones (wifi, iot) also need a UDM policy from Faris.
7. Open the PR. The `pr` workflow lints, runs `catalog.py check`, renders offline and classifies it; see `docs/orchestration.md`.

Guests are created separately in homelab-infra (IP must match the plan). Order for new hosts, flows and removals: 2.2 and 2.4.
